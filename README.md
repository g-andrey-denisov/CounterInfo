# CounterInfo — Telegram-бот поиска и контроля счётчиков электроэнергии

Бот позволяет:
- сканировать штрих-код счётчика (фото) или вводить серийный номер вручную;
- получать данные из корпоративной БД (MariaDB): название, состояние, показания;
- сохранять записи в личный блокнот с произвольным комментарием;
- проводить плановые проверки счётчиков (режим «Чекап»);
- просматривать журнал проверок с фильтрацией по дате;
- получать показания счётчика на конкретную дату (таблица);
- получать показания счётчика за период до 90 дней (таблица по суткам);
- получать помесячный отчёт по счётчику (до 5 лет);
- работать только для авторизованных пользователей (список Telegram ID).

## Требования

- Python 3.11+
- Доступ к MariaDB (`resource@192.168.50.101/resource`)
- Telegram Bot Token от [@BotFather](https://t.me/BotFather)

## Настройка `.env`

```env
BOT_TOKEN=токен_от_BotFather
DB_HOST=192.168.50.101
DB_PORT=3306
DB_USER=resource
DB_PASSWORD=resource
DB_NAME=resource

# Telegram ID администраторов через запятую.
ADMIN_IDS=123456789,987654321
```

Узнать свой Telegram ID можно у [@userinfobot](https://t.me/userinfobot).

### Доступ пользователей

- **Администраторы** (`ADMIN_IDS`) всегда имеют доступ, получают заявки на доступ
  и управляют списком пользователей.
- **Остальные пользователи** хранятся в локальной БД (`data/local.db`). Доступ
  через `.env` больше не выдаётся — только через заявки или вручную.
- Неизвестному пользователю бот предлагает кнопку **«Запросить доступ»**. После
  запроса всем администраторам приходит уведомление с кнопками **«Принять»** /
  **«Отклонить»**; при принятии пользователь получает уведомление о доступе.
- Команда **/users** (только для админов) показывает список пользователей с
  доступом, позволяет удалить любого (с подтверждением) и добавить нового
  вручную по Telegram ID.
- У администраторов своя справка **/help** (с разделом «Администрирование») и
  персональное меню Telegram-команд, где присутствует /users.

## Деплой на Windows

### Разработка (авто-перезапуск при изменении файлов)

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
python run.py
```

### Продакшен — Windows Service через NSSM

[NSSM](https://nssm.cc) оборачивает любой процесс в Windows Service с авто-перезапуском.

```powershell
# Скачать nssm.exe и положить в PATH, затем:
nssm install CounterInfo "C:\path\to\CounterInfo\.venv\Scripts\python.exe" "C:\path\to\CounterInfo\bot.py"
nssm set CounterInfo AppDirectory "C:\path\to\CounterInfo"
nssm set CounterInfo AppStdout    "C:\path\to\CounterInfo\logs\service.log"
nssm set CounterInfo AppStderr    "C:\path\to\CounterInfo\logs\service.log"
nssm set CounterInfo Start        SERVICE_AUTO_START
nssm start CounterInfo
```

Управление:
```powershell
nssm stop CounterInfo
nssm restart CounterInfo
nssm status CounterInfo
```

### Вариант 1 — Системный сервис (рекомендуется для серверов)

Запускается при старте системы от имени отдельного пользователя. Управляется через `sudo`.

**Создать пользователя:**
```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin counterinfo
sudo chown -R counterinfo:counterinfo /opt/CounterInfo
```

**Создать файл сервиса** `/etc/systemd/system/counterinfo.service`:
```ini
[Unit]
Description=CounterInfo Telegram Bot
After=network.target

[Service]
Type=simple
User=counterinfo
WorkingDirectory=/opt/CounterInfo
ExecStart=/opt/CounterInfo/.venv/bin/python bot.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**Включить и запустить:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable counterinfo
sudo systemctl start counterinfo
```

**Управление:**
```bash
sudo systemctl status counterinfo
sudo systemctl stop counterinfo
sudo systemctl restart counterinfo
sudo journalctl -u counterinfo -f        # живые логи
sudo journalctl -u counterinfo --since today
```

### Вариант 2 — Пользовательский сервис (без sudo)

Запускается от имени текущего пользователя. Не требует прав root для управления.
Подходит для VPS, где нет необходимости в изоляции пользователей.

**Разрешить запуск без активной сессии:**
```bash
loginctl enable-linger $USER
```

**Создать файл сервиса** `~/.config/systemd/user/counterinfo.service`:
```bash
mkdir -p ~/.config/systemd/user
nano ~/.config/systemd/user/counterinfo.service
```

```ini
[Unit]
Description=CounterInfo Telegram Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/CounterInfo
ExecStart=/opt/CounterInfo/.venv/bin/python bot.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```

**Включить и запустить:**
```bash
systemctl --user daemon-reload
systemctl --user enable counterinfo
systemctl --user start counterinfo
```

**Управление:**
```bash
systemctl --user status counterinfo
systemctl --user stop counterinfo
systemctl --user restart counterinfo
journalctl --user -u counterinfo -f
```

> **Системный vs пользовательский:**
> | | Системный | Пользовательский |
> |---|---|---|
> | Файл сервиса | `/etc/systemd/system/` | `~/.config/systemd/user/` |
> | Управление | `sudo systemctl` | `systemctl --user` |
> | Запуск при загрузке | Автоматически | Нужен `loginctl enable-linger` |
> | Изоляция | Отдельный системный пользователь | Текущий пользователь |
> | Когда выбрать | Сервер, несколько сервисов | VPS/личная машина |

| Команда / слово | Действие |

| `/clear` или `Очисти` | Очистить блокнот (с подтверждением) |
| `/checkup` или `/check` или `Проверка` | Войти в режим плановой проверки счётчиков |
| `/checkups` или `Проверки` | Журнал проверок (выбор даты, пагинация) |
| `/reading` или `Показания` | Показания счётчика на указанную дату |
| `/period` или `Период` | Показания счётчика за период (до 90 дней, по суткам) |

## Режим проверки (Чекап)

Вход: `/checkup`, `/check` или слово **«Проверка»**.

В режиме доступна постоянная клавиатура:
- **Непроверенные** — список счётчиков без проверки или с давней проверкой (исключает «снят», «демонтирован»), с пагинацией и кнопкой «Выйти»
- **Выйти из режима** — возврат в обычный режим

Сценарий проверки счётчика:
1. Ввести серийный номер, код `N.М` или отправить фото со штрих-кодом
2. Бот показывает данные счётчика из БД (включая текущие показания)
3. Выбрать результат:
   - **Исправен** — запись сохраняется автоматически с комментарием «Проверен, без нареканий»
   - **Контроль** — бот предлагает ввести комментарий, затем сохраняет запись
   - **Отмена** — возврат к вводу следующего счётчика без сохранения
4. После сохранения бот готов к следующему счётчику

В каждую запись сохраняется: дата и время, кто проверял, серийный номер, название, статус, текущие показания из БД и комментарий.

## Журнал проверок (`/checkups`)

1. Бот предлагает выбрать одну из 5 последних дат проверки (кнопки) или ввести дату вручную в формате `дд.мм.гггг`
2. Если за указанную дату записей нет — сообщение об этом и возврат к выбору даты
3. Результаты отображаются постранично (10 записей на страницу): время, проверяющий, счётчик, статус, показания, комментарий

## Показания на дату (`/reading`)

Вход: `/reading` или слово **«Показания»**.

Сценарий:
1. Ввести серийный номер, код `N.М` или отправить фото со штрих-кодом
2. Выбрать дату из кнопок или ввести вручную в формате `дд.мм.гггг`

Кнопки быстрого выбора: 1-й день предыдущего месяца, последний день предыдущего месяца, 1-й день текущего месяца, Вчера, Сегодня.

Бот выводит таблицу:

| Серийный | До | На дату | Итого |
|---|---|---|---|
| 00123456 | 1842 | 1895 | 53 |

- **До** — последние показания перед указанной датой
- **На дату** — показания за указанную дату; если нет — первые после; если нет вообще — `нет`
- **Итого** — разница «На дату» − «До»; `—` если одно из значений отсутствует

## Показания за период (`/period`)

Вход: `/period` или слово **«Период»**.

Сценарий:
1. Ввести серийный номер, код `N.М` или отправить фото со штрих-кодом
2. Выбрать период из кнопок или ввести вручную (максимум 90 дней)

Кнопки быстрого выбора: предыдущий месяц, текущий месяц до сегодня, предыдущая неделя (пн–вс), текущая неделя (пн–сегодня).

Поддерживаемые форматы ручного ввода: `01.01.2024 - 31.01.2024`, `01.01.2024 31.01.2024`, `01.01.2024-31.01.2024`.

Если введена несуществующая дата (например, `31.04.2024`), бот автоматически уменьшает число до последнего дня месяца (`30.04.2024`) и указывает это в отчёте.

Бот выводит таблицу по каждым суткам периода и итоговую строку:

| Дата | До | На дату | Итого |
|---|---|---|---|
| 01.01.2024 | 1842 | 1895 | 53 |
| 02.01.2024 | 1895 | 2010 | 115 |
| 03.01.2024 | 2010 | нет | — |

После таблицы выводятся **первые** и **последние** ненулевые показания за период.

- **До** — последние показания перед началом суток
- **На дату** — показания за данные сутки; если нет — первые после; если нет — `нет`
- **Итого** — разница «На дату» − «До»

## Помесячный отчёт (`/monthly`)

Вход: `/monthly` или слово **«Месяцы»**.

Сценарий:
1. Ввести серийный номер, код `N.М` или отправить фото со штрих-кодом
2. Ввести год (`2024`) или диапазон лет (`2023-2024`), максимум 5 лет

Бот выводит помесячную таблицу. Строки для будущих месяцев не включаются.

| Год | Месяц | До | За месяц | Итого |
|---|---|---|---|---|
| 2024 | Январь | 0 | 1842 | 1842 |
| 2024 | Февраль | 1842 | 1895 | 53 |
| 2024 | Март | 1895 | нет | — |

- **До** — последние показания перед началом месяца; `0` если данных нет
- **За месяц** — последние показания в месяце; `нет` если данных нет
- **Итого** — разница «За месяц» − «До»

## Поиск по коду адреса (формат N.М)

Если ввести текст вида `26.1`, `028.37` или `1,2` (допускаются разделители `.`, `,`, `ю`), бот ищет счётчик по полю `Name`, в котором внутри скобок должен находиться соответствующий код.

Правила нормализации: однозначное число дополняется до двух цифр (`1` → `01`), двух- и трёхзначные используются как есть. Запросы `26.1` и `26.01` эквивалентны, `028.112` и `28.112` — тоже.

## Как работает штрих-код

Штрих-код может содержать серийный номер как подстроку (например, `0385210653426000` содержит серийный `52106534`). Поиск по фото использует `INSTR`, а ручной ввод — точное совпадение.

## Кэш счётчиков

При первом обращении за сутки бот синхронизирует список всех счётчиков из MariaDB в локальный SQLite-файл (`data/local.db`). Список поддерживается актуальным: счётчики, удалённые из основной БД, удаляются и из кэша.

## Локальная база данных (SQLite)

| Таблица | Назначение |
|---|---|
| `notebook` | Личный блокнот пользователя: записи с комментариями |
| `counter_cache` | Кэш всех счётчиков из MariaDB с датой последнего сканирования |
| `cache_meta` | Метаданные кэша (дата последней синхронизации) |
| `checkup` | Журнал плановых проверок: дата, проверяющий, статус, показания, комментарий |
